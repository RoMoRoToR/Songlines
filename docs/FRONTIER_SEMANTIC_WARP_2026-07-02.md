# Фронтир: Семантический варп — навигация по чужой памяти в мультиагентных коллективах

**Дата:** 2026-07-02
**Статус:** research design, готов к инструментализации (Этап W0 — сегодня/завтра)
**Зависимости:** `peer_memory/`, `experiments/collective_semantic_memory/csm_memory.py`, Q/R/M/C logger, roadmap LLM (12.06.2026) — ничего не переписывается, варп-слой только читает логи и добавляет аннотации.

---

## 1. Vision одним абзацем

В культуре songlines человек, знающий песню, может пройти территорию, на которой никогда не был: знание пути передаётся без физического посещения. Мы формализуем это как **семантический варп**: событие, при котором агент материализует и достигает цель, *весь* semantic evidence о которой имеет чужой provenance. Варп — это не пятая стадия Q/R/M/C, а **provenance-предикат на M\***, то есть измерительный слой поверх существующего framework'а. Фронтир-вклад в три хода: (а) первая provenance-обусловленная метрика completion для коллективной памяти — P(C\*|W\*) против P(C\*|M\*, own); (б) **закон дальности варпа** в замкнутой форме, выводимый из CSM-правил trust × staleness и фальсифицируемый экспериментально; (в) **Warp Drive protocol** — optimistic lock + reservation + rollback (anti-M), лечащий известную патологию «misled agent», то есть warp collision.

## 2. Три смысла слова «варп» и какой берём

| Смысл | Откуда | Роль в проекте |
|---|---|---|
| **Warp drive** — мгновенное перемещение | sci-fi / название пакета `songline_drive` | **Главный.** Перенос навигационной компетентности без физического посещения. Определяет событие W\*. |
| **Time Warp** — оптимистичное исполнение с rollback через anti-messages | Jefferson 1985, parallel discrete-event simulation | **Механизм.** Даёт семантику отката для warp collision: anti-M\* событие ретрагирует lock при поступлении conflict/occupancy evidence. Ложится в Этап W3. |
| **Warp** — основа в ткачестве (продольные нити, сквозь которые проходит уток) | текстильная метафора | **Нарратив.** Persistent cross-session память — «основа», эпизоды — «уток». Красиво связывает cross-session persistence (roadmap Этап 4) с варпом через сессии (Этап W4). Не выносится в technical claims. |

Все три смысла согласованы: варп-*событие* (fast travel), варп-*механизм* (rollback), варп-*нить* (persistence). В paper используем первый как определение, второй как архитектурный вклад, третий — одной фразой во введении.

## 3. Формальное ядро

### 3.1 Provenance и foreignness

Каждая единица evidence e, участвующая в merge, уже несёт источник: в `peer_merge.local_merge` pool собирается как кортежи `(agent_id, cid, summary, w)`, где w = trust-вес; в CSM вес равен `trust_i · e^{−α·age}`. Определим:

- **π(e) ∈ {self} ∪ Peers** — provenance функция (уже есть в данных, нужно только протащить в merged view; см. W0).
- **supp(m)** — множество evidence, поддерживающее концепт, на который planner делает lock m = M\*.
- **Foreignness (замеряется строго в момент lock'а):**

```
φ(m) = Σ_{e ∈ supp(m), π(e) ≠ self} w(e)  /  Σ_{e ∈ supp(m)} w(e)
```

Веса w(e) — те же, что использует merge (trust × staleness × confidence), поэтому φ — не новая эвристика, а доля чужой массы *в том самом скоре, по которому planner выбрал кандидата*.

**Важная договорённость:** φ фиксируется в момент M\*. Если агент по дороге сам увидел цель, φ не пересчитывается — иначе каждый успешный варп «размывался» бы собственным подтверждением при подходе, и P(C\*|W\*) стал бы неизмерим.

### 3.2 Событие W\* и семейство метрик

- **W\*_θ := M\* ∧ (φ ≥ θ).** Строгий варп: θ = 1.0 (агент ни разу не наблюдал место сам). Мягкий: θ = 0.8.
- **Warp share:** P(W\*|M\*) — какая доля lock'ов вообще происходит «по чужой песне». Структурный дескриптор архитектуры: у independent тождественно 0; у shared bus ожидаемо максимальна.
- **Warp completion:** P(C\*|W\*) — доводит ли чужая песня до места. Главная новая величина. Сравнивается с P(C\*|M\*, φ < θ).
- **Warp radius ρ:** расстояние (в клетках / graph hops) от visited-set агента до цели в момент W\*. Даёт кривую P(C\*|W\*, ρ).
- **Warp gain (per-episode, каузальный):** благодаря детерминированным сидам и кэшированию возможен **counterfactual replay с маскированием чужого evidence на merge** — тот же сид, тот же planner, но foreign-вклад обнулён. Тогда

```
WG(episode) = t_succ(masked) − t_succ(full)
```

— атрибутируемый выигрыш от варпа, не корреляционный, а контрфактический. Это методологический ход, которого нет у vector-memory систем: их merge не разложим по источникам.

### 3.3 Позиция относительно Q/R/M/C

W не добавляет стадию и не трогает identifiability-теорему. Это **аннотация на M\*-событиях**, разрезающая уже существующие условные вероятности по φ:

```
P(C*|M*) = P(C*|M*, φ<θ)·P(φ<θ|M*) + P(C*|W*)·P(W*|M*)
```

Известный bottleneck-shift (Spearman −0.608 / +0.420 по K) получает механистическое чтение: при малых K растёт именно warp share, и C-collapse концентрируется в W\*-страте. Это проверяемая декомпозиция уже собранных 35 640 прогонов — **их можно переаннотировать без единого нового прогона**, если в логах восстановим provenance (см. риск R3).

### 3.4 Категорная сноска (одним абзацем, для §6 главной статьи)

В provenance-обогащённой Ctx_Σ варп — это M\*, факторизующийся через инъекцию чужого локального контекста в колимит: intention формируется вдоль компоненты merged object'а, прообраз которой целиком лежит в чужой памяти. Три инварианта колимита (order independence, chaining, decay-вне-морфизмов) переносятся без изменений; варп лишь выделяет подкласс использований merged object'а. Больше одного абзаца этому не давать — рецензенты и так настороженно относятся к категорному языку.

## 4. Закон дальности варпа (главное фальсифицируемое предсказание)

CSM-merge включает чужой evidence с весом `trust_i · e^{−α·age}` и порогом включения τ. Значит чужое свидетельство перестаёт формировать intention, когда вес падает ниже τ:

```
age_max(i) = (1/α) · ln(trust_i / τ),   определено при trust_i > τ
```

При дефолтах α = 0.05, τ = 0.30:

| trust_i | age_max, тиков |
|---|---|
| 1.00 | 24.1 |
| 0.80 | 19.6 |
| 0.60 | 13.9 |
| 0.40 | 5.8 |
| ≤ 0.30 | 0 — **варп-гейт закрыт** |

Следствия:

1. **Временной горизонт.** P(C\*|W\*) как функция возраста evidence у CSM должна иметь **излом** около age_max; у fixed-K peer (нет гейта) — гладкое убывание без излома. Различие архитектур на уровне формы кривой, а не средних.
2. **Пространственный радиус.** При скорости 1 клетка/тик эффективный радиус варпа ρ_eff ≈ age_max − age_at_retrieval: агент должен успеть дойти, пока чужая песня «звучит». Неравенство осуществимости варпа:

```
delay_broadcast(≤K) + d(agent, target) ≤ age_max(trust)   — необходимое условие
+ выживание цели (occupancy) на горизонте d              — достаточное в scarcity
```

3. **Trust-flip как выключатель.** Опускание trust к единственному свидетелю ниже τ должно **обнулять** W\*-события целиком (не ухудшать — обнулять). Дискретный, легко проверяемый эффект.
4. **Взаимодействие с pruning.** Снапшоты старше 10K тиков вырезаются; при K = 8 это 80 > 24.1, значит экспоненциальный гейт связывает раньше pruning'а. При K ≤ 2 pruning (20 тиков) начинает конкурировать с гейтом при высоком trust — предсказуемое смещение излома, отдельная ячейка в W2.

Если излом не найдётся там, где предсказано, — это не косметика, а опровержение того, что CSM-правила действительно управляют формированием intention. Любой исход информативен.

## 6. Как варп читает уже полученные результаты

- **Misled-A (раздел 7.5 отчёта 18.05):** A лочится на (3,8), зная о ней только от C, C занимает первым → A застревает. Это строгий варп (φ = 1.0) с collision и без rollback'а. **Эпизод становится regression-якорем W0:** инструментация обязана пометить этот lock как W\*, φ = 1.0.
- **Cadence sweet spot K = 4…8:** умеренная каденция ограничивает *плотность варпов в единицу времени* (warp throughput), снижая collision rate. Cadence-as-coordination = rate-limiter варпа. Старый вывод, новое механистическое чтение.
- **CSM strictly dominates fixed-K:** trust × staleness — это варп-гейт; CSM не «делится лучше», а **отказывается варпать по протухшей или недоверенной песне**. Отсюда удержание обоих conditional links выше 0.78.
- **Shared bus = M-saturation/C-collapse:** максимальный warp share при нулевой стоимости варпа → все варпают в одну точку. Стигмергия муравьёв (феромон) — «анонимный варп» без provenance; наша конструкция — provenance-aware варп, и разница измерима.

## 7. Warp Drive protocol (архитектурный вклад, Этап W3)

Проблема: warp collision — lock по чужому evidence на цель, которую займут раньше. Сегодня агент застревает (misled-A). Решение — три примитива, все с прототипами в кодовой базе:

1. **Optimistic warp lock.** Lock по чужому evidence разрешён сразу (как сейчас), но помечается флагом warp и версией снапшота-источника.
2. **Warp reservation.** При lock'е агент вкладывает в свой следующий broadcast лёгкую резервацию цели (идея Phase 4c `FieldReservation`, перенесённая в peer-режим: резервация — просто поле снапшота, никакого центра). Пиры при merge применяют occupancy-подавление к зарезервированным концептам — децентрализованный аналог ξ·U_t(c).
3. **Anti-M rollback (Time Warp semantics).** При поступлении evidence, несовместимого с lock'ом (цель занята / concept flagged conflict), эмитируется **anti-M\*** событие: lock ретрагируется, кандидат временно подавляется (cooldown с hysteresis — по образцу thirst_on/off), planner немедленно перезапрашивает retrieval. Event bus остаётся append-only: anti-M — это новое событие-ретракция, не мутация истории, инвариант Phase 1 не нарушается.

Q/R/M/C-логгер получает пары (M\*, anti-M\*) и новую величину **rollback latency** — сколько тиков агент терял до перепрограммирования. У misled-A сегодня она равна «до конца эпизода»; протокол обязан сделать её конечной и малой.

Осцилляции (два агента взаимно ретрагируются) гасим exponential backoff на повторный lock той же цели + tie-break по agent_id. Это единственное место, где нужен новый механизм, а не перенос существующего.

## 8. Экспериментальная программа

Каждый этап — independent deliverable; остановка после любого сохраняет ценность предыдущих.

### W0. Инструментация provenance → φ → W\*-аннотация (2–3 дня, ~150 LOC)
**Создаётся:** патч `peer_merge.py`/`PeerView` (протащить per-concept contribution weights — `AgentContribution` уже существует в `consensus_types`), `experiments/warp/warp_instrumentation.py`.
**Что делает:** каждый M\*-лог получает поля `phi`, `w_star_strict`, `w_star_soft`, `warp_radius`, `source_snapshot_age`, `co_recipients`.
**Acceptance:** на пере-прогоне `exp_4way_walk.py` lock агента A на (3,8) помечен φ = 1.0, strict W\*; у independent-варианта W\*-событий ровно 0.

### W1. Warp gain: counterfactual masking sweep (3–4 дня, ~200 LOC)
**Что делает:** subset основного sweep'а (scarcity-ячейки (3,2),(5,3),(8,5) × 3 layout × hazard × 20 сидов) с масками foreign evidence on/off; страты φ.
**Acceptance:** H-W1 и H-W2 получают знаки с CI; карта режимов «где варп помогает / вредит».

### W2. Закон дальности: протокол «свидетель–путник» (3–4 дня, ~150 LOC)
**Что делает:** контролируемая пара агентов. A наблюдает воду в t₀ и замолкает/уходит; B получает снапшот с параметризованным age; свип age × trust × {CSM, fixed-K}.
**Acceptance:** H-W3 — breakpoint у CSM в ±15% от предсказания, отсутствие у fixed-K; таблица age_max(trust) из §4 воспроизведена эмпирически.

### W3. Warp Drive protocol (1–1.5 недели, ~250 LOC)
**Что делает:** reservation-поле в снапшоте + anti-M\* rollback + backoff; прогон при K ∈ {1, 2, 4} против baseline peer и против CSM.
**Acceptance:** H-W4; rollback latency у misled-A конечна; никакой центр не появился (тест: убрать runtime — протокол работает через прямые вызовы, как в 3.6 отчёта).

### W4. Варп через сессии на LLM-подложке (едет на roadmap Этапах 4–5, +2–3 дня инструментации)
**Что делает:** сессия 1 — PeerLLMAgent A исследует комнату в ALFWorld, persistence dump. Сессия 2 — агент B (никогда не видел комнату) получает снапшот A и решает задачу там.
**Acceptance:** в трассе задокументирован **строгий W\* (φ = 1.0) через границу сессии** с C\* = 1 — первый, насколько нам известно, зафиксированный cross-session cross-agent семантический варп на LLM-подложке. Это и есть демо, ради которого пункты 3–4 vision'а (persistence + broadcast) существуют вместе.

**Бюджет суммарно:** ~750 LOC поверх существующего, 2.5–3.5 недели solo-focused; compute $0 на гриде, LLM-часть внутри бюджета roadmap ($200–500). Ничто в roadmap 12.06 не сдвигается: W0–W3 параллельны Этапам 1–3, W4 встраивается в Этапы 4–5.

## 9. Позиционирование: почему это фронтир, а не переупаковка

```
                          делятся памятью │ измеряют provenance-conditioned completion
Generative Agents                ✓        │              ✗
MetaGPT / AutoGen (shared ctx)   ✓        │              ✗ (нет M-lock интерфейса)
Stigmergy / pheromones           ✓ (аноним)│              ✗
Vector memory (MemGPT и др.)     ✓        │              ✗ (merge неразложим по источникам)
Songlines + Warp                 ✓        │              ✓  ◄── ЗДЕСЬ
```

Три вещи, которых нет ни у кого из соседей: (1) W\* как формальное событие с φ, вычисляемым из тех же весов, что использует merge; (2) закон дальности с замкнутой формой и различающим предсказанием формы кривой между архитектурами; (3) контрфактическая атрибуция warp gain через детерминированный replay с маскированием источника. Пустая клетка «symbolic per-agent × multi-agent» из roadmap'а расширяется до «…× provenance-conditioned evaluation».

Paper strategy: либо третья статья серии — «Semantic Warp: Provenance-Conditioned Completion in Collective Memory» (companion к двум существующим, тот же measurement-жанр), либо §7 главной статьи, если W0–W2 успеют до camera-ready. Related work: Generative Agents, Time Warp (Jefferson 1985 — честно взять имя механизма оттуда), TarMAC/CommNet (нет explicit lock), стигмергия (анонимный варп как контраст), songlines-нарратив уже наш.

## 10. Риски

| Риск | Вероятность | Mitigation |
|---|---|---|
| R1. Мало W\*-событий в abundant-режимах — нет статистической мощности | средняя | Oversample scarcity-ячеек; θ = 0.8 как рабочий, θ = 1.0 как строгая страта |
| R2. φ размывается само-подтверждением при подходе к цели | высокая без договорённости | Определение §3.1: φ замораживается в момент M\*. Зафиксировано в инструментации, не в анализе |
| R3. Старые логи 35 640 прогонов не содержат provenance для переаннотации | средняя | Детерминированные сиды → дешёвый re-run нужного subset'а с W0-инструментацией; переаннотация — бонус, не зависимость |
| R4. Rollback осциллирует | средняя | Backoff + hysteresis + tie-break (§7); метрика rollback latency ловит патологию сразу |
| R5. Излом маскируется pruning'ом при малых K | низкая | Предсказано в §4 п.4 — включено в дизайн W2 как отдельная ячейка, не сюрприз |
| R6. Рецензенты: «варп — переименованный information sharing» | средняя | Ответ готов: sharing — про канал, варп — про *использование* (lock + completion) с каузальной атрибуцией; H-W3/H-W5 не формулируются в терминах канала вовсе |
